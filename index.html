The 60-Second Mental Model

If you have never touched a code repository or pipeline, here is how Git actually works in plain English.

📁
The Repository ("Repo")
What is it?

Think of a repo as your normal project folder, but with an automatic time machine attached. It tracks every file you touch and remembers its entire history.

💾
The Commit
A Game Save Point

You wouldn't play an RPG for 10 hours without saving. A commit is a permanent checkpoint. If your experiment fails tomorrow, you can rewind time back to this exact second.

🛒
The Staging Area (git add)
Your Shopping Cart

Before you buy items at a store, you place them into a cart. git add puts your edited files in the cart. git commit is paying at the register to seal the checkpoint.

☁️
Remote & Pipelines
Cloud Backup & Robot Helper

GitHub is Google Drive for code. A Pipeline is a robot in the cloud that automatically inspects, tests, and publishes your website the moment you push.

Saving Your Work (Checkpoints)
Daily Essential
In plain English: Tell Git "I just finished a small task. Lock in a checkpoint so I can never lose this work."
Check status and save 
# 1. See what you edited:
git status

# 2. Put files into the cart:
git add <filename>   # Or 'git add .' for everything

# 3. Create the permanent checkpoint:
git commit -m "Explain what changed"
Best Practice: Commit often! Small checkpoints make it trivial to locate bugs later.
Branches: Your Risk-Free Sandboxes
Branches
In plain English: Want to test an idea without breaking your working project? A branch is a parallel sandbox. If it fails, delete it. If it works, merge it back.
Create & Switch Sandbox 
# Create and jump into a new sandbox:
git switch -c new-feature-experiment

# Work safely, edit files, and commit:
git add .
git commit -m "Trying a new design"

# Jump back to the main safe project:
git switch main
TaskModern (Easy)Old Way (Confusing)
Switch sandbox git switch <name> git checkout <name>
Create sandbox git switch -c <name> git checkout -b <name>
Undoing Mistakes Without Panicking
Undo Mistakes
In plain English: You wrote broken code and want to throw away your unsaved edits and restore the last working checkpoint.
Discard & Unstage 
# "I messed up this file, throw away my edits":
git restore <filename>

# "I accidentally ran 'git add', take it out of the cart":
git restore --staged <filename>

# "I want to undo the last public commit safely":
git revert <commit-id>
Syncing with GitHub (The Cloud)
Cloud & Sync
In plain English: Share your checkpoints with teammates or backup your project on GitHub.
Push & Pull 
# Upload your checkpoints to GitHub:
git push

# Download your teammates' latest updates:
git pull

# First time linking your project to GitHub:
git remote add origin <url-from-github>
git push -u origin main
What is a "Pipeline" (CI/CD)?
Cloud & Sync
In plain English: Whenever you push code to GitHub, an automated robot in the cloud runs checks to see if anything broke, then publishes your app live.

You don't have to manually FTP or upload files to a web server. The pipeline watches your main branch and deploys automatically!

In this repository, our pipeline file is located at .github/workflows/deploy.yml. Whenever you push, GitHub Pages publishes this guide automatically!
Stashing: The "Pause Button"
Daily Essential
In plain English: You are halfway through coding when your boss asks you to fix an urgent bug. You can shelf your messy work on a virtual shelf, fix the bug, and restore it later.
Pause & Resume 
# 1. Put uncommitted work on the shelf:
git stash push -m "Halfway through login page"

# 2. Your project is now clean! Do your quick fix...

# 3. Take your work back off the shelf:
git stash pop
Merge Conflicts Demystified
Branches
In plain English: You and a teammate both edited the exact same line of code in the same file. Git halts and politely asks: "Which version do you want to keep?"
How to resolve 
# 1. Git marks the clash in your file like this:
<<<<<<< HEAD (Your version)
color: blue;
=======
color: red; (Teammate version)
>>>>>>> main

# 2. Simply delete the markers and keep the right code!
# 3. Tell Git you resolved it:
git add <filename>
git merge --continue
Interactive Rebase (Commit Polish)
Advanced / Pro

Squash micro-commits into clean milestones before merging into production.

Rebase
git rebase -i HEAD~3
# squash = combine into previous commit
# reword = edit commit message
Detached HEAD Recovery
Advanced / Pro

Occurs when you checkout a commit hash instead of a branch pointer.

Escape Detached State
git switch main               # Return to main branch
git switch -c recovery-branch # Save experimental commits
Git Worktrees (Parallel Folders)
Advanced / Pro

Check out two branches simultaneously into different folders on disk.

Worktree Commands
git worktree add ../hotfix-folder hotfix-branch
git worktree list
git worktree remove ../hotfix-folder
